# The failsafe control plane verifies operator command signatures with the
# SAME definition the engine uses, so the two never disagree. It imports
# mythos_core.failsafe (which brings cryptography transitively) at URLconf
# load, so the light CI set needs it too -- leaving it out took the whole URL
# conf down. cryptography is named directly because signing.py imports it
# directly. mythos-core is a private git pin; CI clones it with a
# MYTHOS_CORE_TOKEN secret (see the workflow's auth step), as on the engines.
# Pinned to the v0.2.2 release commit (tag refs cannot be pushed from these
# sessions -- the remote answers 403 for refs/tags/*; see Mythos-Core#10); it also
# carries mythos_core.tracing. This pin and the one in requirements.txt must name
# the SAME commit -- two files that can drift apart would install two different
# foundations for the same service, and tests/test_mythos_core_pin.py fails if
# they ever disagree.
cryptography>=41.0
mythos-core @ git+https://github.com/Deltawsierra/Mythos-Core@b66bdea28af83a49ff1ed34683df95b54283b3d2
